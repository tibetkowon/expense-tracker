# 지출 추적 앱 (Expense Tracker) — 설계 문서

- 날짜: 2026-09-01
- 상태: 초안 (사용자 리뷰 대기)

## 1. 목적

개인 지출을 수집해서 사용자 본인의 Google Drive에 Google Sheets로 정리해주는 개인용 도구를 만든다. 최종 목표는 "자동으로 지출/소비패턴을 수집·분석"하는 것이지만, 조사 결과 완전 자동 수집에는 구조적 제약이 있어 1단계는 수동 입력 기반 MVP로 시작하고, 자동 수집은 실사용 데이터가 쌓인 뒤 재검토한다.

## 2. 배경 조사 (Phase 1): 지출 수집 방법 검토

여러 자동 수집 경로를 조사했고, 각각 다음과 같은 한계로 채택하지 않았다. 향후 재검토 시 참고할 것.

| 방법 | 결론 | 이유 |
|---|---|---|
| 오픈뱅킹 공식 API | 제외 | 개인 프로젝트로는 이용기관 등록/심사 절차가 사실상 불가능 |
| 마이데이터 API | 제외 | 마이데이터 사업자 라이선스 보유 기업만 접근 가능 |
| CODEF (금융 데이터 어그리게이터) | 보류 | 카드/계좌 직결제는 자동 수집 가능하나, 데모버전은 1개월 한정이고 정식버전 요금이 "별도상담"으로 비공개. 장기 지속가능성 불확실. 페이앱 충전금(토스머니 등) 지출은 CODEF의 PG API로도 커버 안 될 가능성 높음(PG API는 가맹점용으로 추정) |
| SMS 문자 파싱 (단축어 자동화) | 제외 | 기술적으로는 가능(iOS 단축어 "메시지 받으면" + "실행 전 묻기" 끄기)하나, 사용자의 실제 알림 수신 방식이 문자가 아닌 앱 푸시임 |
| 앱 푸시 알림 파싱 | 제외 (불가능) | iOS는 한 앱이 다른 앱의 푸시 알림 내용에 접근하는 것을 시스템 차원에서 차단. Android의 NotificationListenerService 같은 공개 API가 iOS엔 없음. 우회 불가 |
| 이메일 결제알림 파싱 (Gmail API) | 보류 | 페이앱들이 결제 건별 이메일을 안정적으로 보내는지 확인 안 됨. 재검토 후보로 남겨둠 |
| 영수증 사진 OCR | 채택 (보조) | 수동 촬영이 필요해 완전 자동은 아니지만, 데이터 입력 부담을 크게 줄여줌 |
| 수동 입력 | 채택 (1차 MVP 핵심) | 가장 확실하고 무료. 자동화 부재의 한계를 인지하고 시작 |

**사용자의 실제 결제 패턴**: 토스/카카오페이/네이버페이(충전금·카드·계좌 혼재), KB카드, 현대카드, K뱅크, KB은행 — 알림은 전부 앱 푸시로 수신. 카드/은행 SMS 알림 서비스는 존재하나 별도 비용 발생으로 전환하지 않기로 함.

## 3. 기능 범위 (Phase 2): MVP

1. 지출 수동 입력 — 날짜/금액/카테고리/메모/결제수단
2. 영수증 사진 업로드 → OCR 자동 인식(Gemini Vision) → 사용자 확인/수정 후 저장 (자동 초안 + 사람 확인 방식으로, OCR 오인식이 그대로 누적되는 것을 방지)
3. Google Sheets 자동 저장 (지정 스프레드시트에 행 추가)
4. 카테고리 관리 — 기본 카테고리 + 커스텀 추가
5. 최근 내역 조회 및 월별 합계
6. 시트 저장 폴더 지정 — Google Picker로 본인 Drive의 기존 폴더를 선택. 선택한 폴더 ID는 서버 DB 없이 브라우저 localStorage에 저장(단일 기기 개인용 앱 전제). 미선택 시 Drive 루트에 생성/검색(기존 동작 유지)

### 2단계 확장 후보 (MVP 이후, 아직 미착수)
- 이메일 결제알림 자동 파싱 (Gmail API)
- CODEF 카드/계좌 연동 (정식 요금 확인 후 재검토)
- 카테고리별 통계/그래프 대시보드
- 예산 설정 및 초과 알림

## 4. 기술 스택 (Phase 3)

| 항목 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js (App Router) | Vercel과 제로 설정으로 통합, PWA 구성 패턴이 잘 갖춰짐 |
| 배포 | Vercel | 무료 티어로 충분, 프리뷰 배포로 반복 검증 가능 |
| 형태 | PWA (모바일 웹) | 앱스토어 심사·연 $99 개발자 계정 없이 즉시 배포/업데이트 가능. 홈 화면 추가로 앱과 유사한 사용성 확보 |
| 인증 | Google Sign-In (클라이언트), `drive.file` 스코프 | 개인 단일 사용자용. `drive.file`은 앱이 생성한 파일만 접근하는 최소 권한이라 광범위한 Drive 접근 승인 없이 사용 가능. 서버에 OAuth 토큰을 영구 저장할 필요 없음(자동 수집을 보류했으므로 상시 서버 접근 불필요) |
| 저장소 | Google Sheets API만 사용, 별도 DB 없음 | 개인 가계부 규모에서 DB 추가는 과설계. Sheets 자체가 "구글 드라이브에 정리"라는 요구사항과 정확히 일치 |
| OCR | Gemini API (Vision), Flash/Flash-Lite 모델 | 순수 OCR이 아니라 이미지→구조화 JSON(날짜/금액/상호명) 추출까지 한 번에 처리. 무료 티어(하루 최대 1,000회)로 개인 사용량 충분. 유료 전환되어도 영수증 1장당 약 0.1~0.4원 수준으로 사실상 무시 가능 |
| 폴더 선택 | Google Picker API | 사용자가 Drive에서 기존 폴더를 직접 골라 그 안에 시트를 두게 함. Picker로 선택한 항목은 `drive.file` 스코프에서도 접근 허용되므로 광범위한 Drive 권한 요청 없이 구현 가능 |

**추가로 활성화해야 하는 Google Cloud API**: Google Drive API, Google Sheets API, Google Picker API 세 가지 모두 Cloud Console의 "API 및 서비스 → 라이브러리"에서 켜야 함 (OAuth 클라이언트 생성만으로는 자동 활성화되지 않음).

## 5. 개발 워크플로우

Claude Code(감독)와 Codex(실무)가 아래 루프로 협업한다. 기존에 설치된 `codex:rescue`, `codex:setup` 플러그인을 활용한다.

1. Claude Code가 작업을 명확한 스펙(파일 범위, 요구사항, 완료 기준)으로 정리
2. Codex가 `codex:rescue`를 통해 실제 구현 수행
3. Codex가 변경사항과 특이사항(가정, 트레이드오프, 남은 이슈)을 자체 리뷰로 요약해 반환
4. Claude Code가 리뷰 내용을 검증·정리해서 사용자에게 보고
5. 필요 시 오류·보완사항을 Codex에게 다시 전달해 후속 조치

## 6. 프로젝트 메모리 관리 (CLAUDE.md)

- CLAUDE.md에 "최근 결정 사항" 섹션을 두고, 기능 단위 작업이 끝날 때마다 `claude-md-management:revise-claude-md` 스킬로 갱신 (개발 워크플로우 5단계 이후 이어붙임)
- 트리거: 세션 종료 시 Stop 훅으로 revise-claude-md 실행 여부를 확인 (추후 `update-config` 스킬로 설정)
- "문제 발생 시 자동 업데이트"는 완전 자동 판단이 불가능하므로, 매 세션 종료 시 방향성이 바뀐 결정이 있었는지 점검하고 반영하는 방식으로 갈음

## 7. 미해결 사항 / 향후 재검토

- CODEF 정식버전의 개인 규모 실제 요금 — 미확인, 필요 시 직접 문의
- 페이앱 충전금 지출의 자동 수집 방법 — 현재 경로 없음
- Google Cloud 프로젝트의 OAuth 동의 화면 설정 — 실제 구현 단계에서 처리 필요

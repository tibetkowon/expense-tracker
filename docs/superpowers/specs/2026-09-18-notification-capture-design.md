# 결제 알림 자동 캡처 — 설계 문서

- 날짜: 2026-09-18
- 상태: 초안 (사용자 리뷰 대기)
- 배경: iOS 27부터 단축어(Shortcuts) 앱이 알림의 앱 이름/본문 텍스트를 자동화 트리거로 읽을 수 있게 됨. 사용자가 이 기능으로 카드사 결제 알림(예: "[현대카드] 고원 님, 현대 ZERO 승인 40,495원 일시불, 9/17 13:09 (주)오리온 누적1,161,364원")을 메모에 저장하는 걸 확인, 같은 알림을 이 앱의 "확인 대기" 초안으로 바로 보내고 싶어함. 여러 카드사/은행 앱을 쓰고 있어 알림 포맷이 제각각이라, 단축어 내부 정규식 파싱이 아니라 서버 쪽에서 기존 영수증 OCR과 같은 Gemini 기반 파싱을 재사용하기로 함.

## 1. 목표

- 결제 알림이 올 때마다 화면이 뜨는 방해 없이(백그라운드 캡처), 그렇다고 확인 없이 자동 저장되지도 않게(기존 OCR과 동일한 human-confirm 원칙, `CLAUDE.md` "OCR must never auto-save" 제약을 이 경로에도 동일 적용) 만든다.
- 사용자는 결제 시점엔 아무 화면도 보지 않고, 원하는 시점에 앱을 열어 쌓인 항목을 몰아서 확인/저장한다.

## 2. 결정된 방향 (요약)

- iOS 단축어 자동화가 알림을 감지해 화면 없이(백그라운드) 텍스트를 서버로 전송한다.
- 서버는 기존 영수증 OCR과 동일한 모델(`gemini-3.5-flash-lite`, Vertex AI)로 텍스트를 파싱해 `결제`/`입금`/`취소`를 분류하고 필드를 추출한다.
- `입금`은 무시한다. `결제`/`취소`는 스프레드시트의 새 `대기` 탭에 한 줄 추가한다.
- 사용자는 대시보드의 "확인 대기" 섹션에서만 이 항목들을 본다. `결제` 항목은 확인 후 저장하면 실제 월별 탭으로 이동하고, `취소` 항목은 원거래를 사용자가 직접 찾아 지우도록 안내하는 리마인더로만 동작한다.
- 단축어 → 서버 호출은 고정 API 키로 인증한다. 서버 → 시트 쓰기는 사용자의 브라우저 세션과 무관하게 항상 동작해야 하므로 별도의 구글 서비스 계정을 사용한다.
- 알림(푸시)은 보내지 않는다 — "결제할 때마다 화면이 뜬다"는 원래 불편함을 피하기 위한 선택이며, 그 트레이드오프는 §8에서 다룬다.

## 3. 인증 설계 — 왜 서비스 계정인가

현재 `lib/sheets.ts`의 모든 함수는 `accessToken: string`을 받아 `google.auth.OAuth2().setCredentials({ access_token })`으로 인증한다. 이 토큰은 `auth.ts`가 관리하는 브라우저 세션(JWT 쿠키) 안에만 존재한다. 단축어 호출은 브라우저 세션이 없는 백그라운드 호출이라 이 토큰에 접근할 수 없다.

- **기각한 대안 — 사용자 리프레시 토큰을 서버에 영구 저장**: 한 번 오프라인 동의를 받아 리프레시 토큰을 발급받고 서버에 보관하는 방법도 가능하지만, 6개월 미사용이나 비밀번호 변경 시 조용히 끊기는 리스크가 있고, 이 앱의 "DB 없음" 원칙과도 결이 다른 사용자별 영구 자격증명을 새로 관리해야 한다.
- **채택한 대안 — 서비스 계정**: 기존 Vertex AI 연동(`GOOGLE_VERTEX_CREDENTIALS`, `lib/ocr.ts`)과 완전히 같은 패턴. GCP 콘솔에서 사람이 아닌 전용 계정을 1회 생성하고, 사용자가 앱 내 버튼으로 자신의 스프레드시트를 그 계정과 공유한다. 사용자 로그인 상태/토큰 만료와 무관하게 항상 유효하다.

**설정 흐름:**
1. (수동, 1회) GCP 콘솔에서 서비스 계정 생성 → JSON 키 발급 → Vercel 환경변수 `SHORTCUT_SERVICE_ACCOUNT_CREDENTIALS`로 저장. 서비스 계정 이메일은 `SHORTCUT_SERVICE_ACCOUNT_EMAIL`로 별도 저장(클라이언트에도 노출 가능한 값).
2. (앱 내, 1회) 설정 화면에 "단축어 연동 켜기" 버튼 추가. 클릭 시 `POST /api/shortcuts/link-sheet` 호출 → 현재 로그인 세션의 `drive.file` 권한으로 Drive API `permissions.create`를 호출해 `SHORTCUT_SERVICE_ACCOUNT_EMAIL`을 해당 스프레드시트의 편집자로 추가한다. 새로운 OAuth 스코프는 필요 없다 (`CLAUDE.md`의 스코프 제약 유지).
3. (수동, 1회) 사용자가 `SHORTCUT_API_KEY` 환경변수를 하나 정해 Vercel에 등록하고, 같은 값을 iOS 단축어의 요청 헤더에 붙여넣는다. 발급/회전 UI는 만들지 않는다(YAGNI, 개인용 단일 값).

## 4. 데이터 모델 — `대기` 탭

기존 월별 탭(`YYYY-MM`)과 나란히, 스프레드시트 안에 `대기` 탭을 하나 추가한다.

| 날짜 | 금액 | 카테고리 | 메모 | 결제수단 | 유형 | 원문 |
|---|---|---|---|---|---|---|

- `유형`: `결제` 또는 `취소`.
- `원문`: 단축어가 보낸 알림 텍스트 그대로. 파싱이 애매하거나 실패한 필드가 있어도 이 컬럼은 항상 채워져서, 사용자가 확인 화면에서 직접 참고해 빈 칸을 채울 수 있다.
- 헤더 생성/멱등성은 기존 `ensureMonthSheet`(`lib/sheets.ts:48`)와 동일한 2단계 패턴(`addSheet` → 헤더가 없을 때만 `values.update`)을 따른다.
- 행 식별은 기존 월별 탭과 동일하게 스프레드시트 행 번호를 그대로 쓴다(별도 ID 컬럼 없음 — 기존 "Row identity is the spreadsheet row number" 관례 유지).
- **중복 방지**: 새 항목을 추가하기 전에 `원문` 컬럼에 동일한 텍스트가 이미 있는지 확인하고, 있으면 조용히 스킵한다.

## 5. 신규/변경 파일

- `lib/pending.ts` (신규): `대기` 탭 전용 read/append/delete + 중복 검사. `lib/sheets.ts`의 기존 함수(`appendExpenseRow` 등)는 5컬럼 스키마라 그대로 재사용하지 않고, 7컬럼용 함수를 별도로 둔다.
- `lib/notificationParse.ts` (신규): `lib/ocr.ts`의 `extractReceiptData`와 같은 구조(Vertex AI + `Output.object`)로, 이미지 대신 텍스트를 입력받아 `{ type: '결제'|'입금'|'취소', date, amount, merchant, categoryGuess, method }`를 추출.
- `app/api/shortcuts/parse/route.ts` (신규): 단축어가 호출하는 엔드포인트. API 키 인증 + 서비스 계정으로 시트 접근.
- `app/api/shortcuts/link-sheet/route.ts` (신규): "단축어 연동 켜기" 버튼용. 사용자 세션 인증 + Drive `permissions.create`.
- `app/api/pending/route.ts` (신규): `GET`(목록 조회), `DELETE`(항목 삭제/무시) — 기존 `/api/expenses`처럼 사용자 세션 인증.
- `app/api/pending/confirm/route.ts` (신규): `POST` — 결제 항목 확인 시 실제 월별 탭에 추가 + 대기 탭에서 삭제를 한 번에 처리.
- `components/ExpenseDashboard.tsx` (수정): "확인 대기" 섹션 추가, `/api/pending` 조회를 `fetchMonth`와 나란히 수행.
- `components/PendingList.tsx` (신규): 대기 항목 렌더링, 결제 항목은 `ExpenseForm` prefill로 연결, 취소 항목은 리마인더 카드로 렌더링.
- 설정 화면 어딘가(예: `FileNameSetting.tsx` 근처)에 "단축어 연동 켜기" 버튼 추가.

## 6. API 설계

### `POST /api/shortcuts/parse`

- 인증: 요청 헤더의 API 키를 `SHORTCUT_API_KEY`와 비교. 불일치 시 401.
- Body: `{ appName: string, text: string }`.
- 처리: `notificationParse`로 파싱 → `type === '입금'`이면 아무 것도 쓰지 않고 `{ ok: true, skipped: true }` 반환 → 그 외에는 서비스 계정으로 `대기` 탭에 추가(중복이면 스킵)하고 `{ ok: true }` 반환.
- Gemini/시트 오류는 500으로 명확히 응답한다(기존 `/api/ocr`처럼 에러를 삼키지 않음). 다만 이 호출의 결과를 사용자에게 보여주는 알림은 없으므로(§8), 실패는 서버 로그에만 남는다.

### `POST /api/shortcuts/link-sheet`

- 인증: 기존과 동일한 사용자 세션(`auth()`).
- 처리: 현재 스프레드시트를 `SHORTCUT_SERVICE_ACCOUNT_EMAIL`과 편집자 권한으로 공유.

### `GET /api/pending`

- 인증: 사용자 세션. `findOrCreateSpreadsheet`로 같은 파일을 찾아 `대기` 탭을 읽는다.

### `DELETE /api/pending`

- Body: `{ folderId, fileName, rowNumber }`. 대기 탭에서 해당 행만 삭제. 결제 항목의 "무시" 버튼과 취소 항목의 "확인" 버튼이 공용으로 사용.

### `POST /api/pending/confirm`

- Body: `{ folderId, fileName, pendingRowNumber, ...expenseInput }`(기존 `ExpenseInputSchema`).
- 처리: `appendExpenseRow`로 실제 월별 탭에 기록 → 성공하면 대기 탭에서 `pendingRowNumber` 삭제.

## 7. UI 흐름

`ExpenseDashboard`에 "확인 대기 (N)" 섹션을 추가한다(항목이 없으면 섹션 자체가 안 보임).

- **결제 항목**: 탭하면 기존 영수증 OCR 초안과 동일한 방식으로 `ExpenseForm`이 미리 채워짐. 사용자가 확인/수정 후 저장하면 `/api/pending/confirm` 호출. 항목별 "무시" 버튼으로 로그 없이 삭제 가능(`DELETE /api/pending`).
- **취소 항목**: 폼을 열지 않는다. 파싱된 가맹점/금액/날짜와 "이 거래를 지출 목록에서 찾아 직접 삭제해 주세요" 안내, "확인" 버튼(`DELETE /api/pending`)만 제공. 원거래 자동 매칭/삭제는 하지 않는다(§9에서 이유 설명).

## 8. 에러 처리 / 알려진 트레이드오프

- 알림(푸시)을 보내지 않기로 했기 때문에, `/api/shortcuts/parse` 호출이 실패해도(서비스 계정 접근 취소, 자격증명 만료 등) 사용자는 즉시 알 방법이 없다. 대기 목록에 새 항목이 하루 이상 안 쌓이는 걸로만 간접적으로 눈치챌 수 있다. 이건 "결제마다 방해받고 싶지 않다"는 원래 요구사항을 지키기 위해 받아들이는 트레이드오프이며, 이번 스펙 범위에서는 헬스체크/모니터링을 추가하지 않는다.
- `/api/pending/confirm`의 두 단계 쓰기(월별 탭 추가 → 대기 탭 삭제)는 원자적이지 않다. 첫 단계 성공 후 두 번째가 실패하면 같은 지출이 대기 탭과 월별 탭 양쪽에 남을 수 있다 — 사용자가 대기 목록에서 다시 확인하면 중복 저장 없이 그냥 "무시"로 지우면 되므로 심각한 문제는 아니다.

## 9. 취소 항목을 리마인더로만 처리하는 이유

취소 알림을 받았을 때 원거래를 자동으로 찾아 지우는 방법도 검토했으나(가맹점명+금액+근접 날짜로 매칭), 다음 이유로 채택하지 않았다:
- 원거래가 이미 사용자에 의해 수정됐거나 다른 달 탭으로 이동했을 수 있어 매칭이 틀릴 위험이 있다.
- 잘못 매칭해 엉뚱한 지출을 삭제하는 건 되돌리기 어려운 실수이며, 이 프로젝트가 지금까지 일관되게 지켜온 "사람이 최종 확인" 원칙과 맞지 않는다.
- 음수 금액으로 상쇄하는 방법도 검토했으나, `ExpenseInputSchema`(`lib/expense.ts:5`)가 `amount: z.number().positive()`로 전체 앱에서 금액을 양수로 제약하고 있어 이를 완화하는 건 이번 기능 범위를 넘는 더 큰 변경이 된다.

## 10. 비용

`gemini-3.5-flash-lite` 기준(입력 $0.30/1M 토큰, 출력 $2.50/1M 토큰), 알림 텍스트 파싱 1건당 약 $0.0004(0.5원 내외). 하루 5~10건 결제 기준 월 100~150건 호출로도 월 100~150원 수준이라, 기존 Google Developer Program 크레딧으로 충분히 커버된다.

## 11. 이 스펙에서 다루지 않는 것

- iOS 단축어 앱 내부 구성(자동화 트리거, "URL 콘텐츠 가져오기" 액션 설정 등) — 이건 저장소 밖 클라이언트 설정이라 스펙 문서로 관리하지 않는다. 구현 완료 후 사용자가 단축어를 직접 만들 때 필요한 엔드포인트 URL/요청 형식만 안내한다.
- 여러 카드사 알림 포맷 전수 테스트 — Gemini 프롬프트가 일반화해서 처리하되, 특정 포맷이 계속 실패하면 추후 프롬프트를 따로 튜닝한다.
- 실패 모니터링/헬스체크(§8) — 필요해지면 별도 스펙으로 재검토.
- 대기 항목 자동 만료/정리.
- 취소 알림의 원거래 자동 매칭/삭제(§9).

## 12. 미해결 사항

- 카드사별 알림 문구 포맷 편차에 대한 실제 파싱 정확도는 구현 단계에서 실제 알림 샘플 몇 개로 검증이 필요하다.
- 서비스 계정 키의 로테이션 정책은 정하지 않았다 — 기존 Vertex AI 자격증명과 동일한 수준(유출 시에만 재발급)으로 취급한다.

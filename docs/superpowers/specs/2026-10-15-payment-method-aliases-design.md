# 결제수단 알림 표기 매칭 · 결제수단 관리 · 대기 목록 접기 — 설계 문서

- 날짜: 2026-10-15
- 상태: 사용자 승인된 방향 (구현 대기)
- 배경: 알림마다 결제수단 표기가 제각각(카드 끝 4자리, 카드명, 계좌번호 등)이라 자동 알림 항목마다 결제수단을 손으로 골라야 한다. 또 화면 진입 시 확인 대기 목록이 늦게 로딩되어 아래 내용이 밀린다.
- 관련: `2026-09-08-payment-method-management-design.md`(설정 시트 A열), `2026-09-18-notification-capture-design.md`(알림 수집)

## 1. 데이터 모델

`설정` 시트에 B열을 추가한다.

| A (결제수단) | B (알림 표기) |
|---|---|
| 신한카드 | 1234, Deep Dream |
| 국민은행 | 123-45-6789, 국민 ****6789 |

- `B1` 헤더: `알림 표기`. B열이 비어 있어도 기존 동작은 그대로(하위 호환). 헤더가 없는 기존 시트는 쓰기 시점에 B1을 채운다.
- B 셀은 쉼표(`,`)로 구분한 표기 목록. 앞뒤 공백 제거, 빈 항목 무시.
- 기존 `listPaymentMethods`(string[] 반환)는 시그니처 유지(기존 호출부 호환). 별칭까지 읽는 새 함수를 추가한다 (예: `listPaymentMethodEntries` → `{ name, aliases: string[] }[]`).

## 2. 알림 수신 시 자동 매칭 (`app/api/shortcuts/parse`)

- 서비스 계정 인증으로 `설정` 시트를 읽는다(이미 대기 시트에 쓰는 것과 같은 인증·스프레드시트).
- 매칭 대상 텍스트: 알림 원문(`text`)과 AI가 추출한 `extraction.method`.
- 규칙(순수 함수로 분리해 단위 테스트):
  1. 대소문자·공백 무시 부분 일치.
  2. 숫자/숫자·하이픈만으로 된 표기(끝 4자리, 계좌번호)는 앞뒤가 숫자·쉼표에 붙어 있지 않을 때만 일치(금액 `11,234원`이 `1234`로 오매칭되지 않게).
  3. 여러 개가 일치하면 가장 긴 표기 우선, 길이가 같으면 시트 위쪽 행 우선.
  4. 일치하면 `method`를 A열 이름으로 대기 행에 기록.
- **매칭 실패 시**: 지금처럼 AI가 뽑은 원본 문자열을 그대로 `method`에 기록(빈 값이면 빈 값). 대기 목록에서 원문 표기가 보여야 §3 기억하기를 쓸 수 있다.
- 설정 시트 읽기가 실패해도 알림 저장은 막지 않는다(매칭만 건너뛰고 원본 문자열 사용).

## 3. 확인 시 "이 표기 기억하기"

- 대기 항목을 확인(`PendingList` → 폼 프리필 → 저장)할 때, 대기 행의 원본 `method`가 비어 있지 않고 사용자가 최종 선택한 결제수단과 다르면, 폼에 체크박스 `알림 표기 "{원본}"를 "{선택한 결제수단}"으로 기억` 을 보여준다(기본 체크).
- 체크된 채 저장하면 `POST /api/pending/confirm`에 `rememberAlias: string`을 함께 보내고, 서버는 지출 저장·대기 행 삭제와 함께 해당 결제수단 행 B열에 표기를 추가한다(이미 있으면 무시, 결제수단 행이 없으면 `ensurePaymentMethodRegistered`로 먼저 등록).
- 별칭 저장이 실패해도 지출 저장 자체는 성공으로 처리한다(별칭은 부가 기능).

## 4. 결제수단 관리 화면

별도 클라이언트 컴포넌트(예: `PaymentMethodManager`)를 대시보드에 접이식 섹션으로 추가한다(기본 접힘).

- 목록: 결제수단 이름 + 알림 표기 목록 표시.
- 추가: 이름(필수) + 알림 표기(선택, 쉼표 구분).
- 수정: 이름 변경, 알림 표기 편집.
- 삭제: 설정 시트에서 해당 행만 제거. **기존 지출 기록은 건드리지 않는다**(확인 문구에 명시).
- 이름은 비어 있을 수 없고 기존 이름과 중복 불가(409 반환).

API: `app/api/payment-methods/route.ts` — `GET`(목록+별칭), `POST`(추가), `PATCH`(이름 변경 및/또는 별칭 변경), `DELETE`. 인증·`folderId`/`fileName` 전달 방식은 기존 `/api/expenses`와 동일하게 따른다(fetch 시점 위치 고정 규칙 포함).

## 5. 이름 변경 시 기존 기록 일괄 수정

가능하다. 결제수단은 모든 월 시트 5번째 열(E)과 `대기` 시트 5번째 열(E)에 문자열로 저장되어 있으므로 일괄 치환할 수 있다.

`PATCH`로 이름이 바뀌면 서버가 순서대로:
1. 모든 월 시트(`YYYY-MM`)의 `E2:E`를 읽어 이전 이름과 정확히 같은 셀만 새 이름으로 갱신.
2. `대기` 시트가 있으면 동일하게 `E2:E` 치환.
3. 마지막에 `설정` 시트 A열(및 B열)을 갱신.

- Sheets에는 트랜잭션이 없으므로 **설정 시트를 마지막에** 바꾼다. 중간에 실패하면 설정은 옛 이름 그대로 남아 같은 요청을 다시 보내면 이어서 처리된다(치환은 멱등).
- 응답에 치환한 행 수를 포함해 UI에서 "N건의 기록도 함께 수정했어요"로 알린다.
- 새 이름이 다른 기존 결제수단과 같으면 거부(합치기는 이번 범위 밖).

## 6. 확인 대기 목록 접기 (로딩 시 레이아웃 밀림 해결)

- `PendingList` 헤더(`확인 대기 (N)`)를 항상 렌더링하고, 본문은 접기/펼치기. **기본 접힘**, 펼침 상태는 `localStorage`에 저장(접근 실패해도 동작하도록 try/catch, 기본 접힘으로 폴백).
- 불러오는 중에는 헤더에 `확인 대기 (불러오는 중…)`처럼 같은 높이로 표시해, 데이터가 도착해도 헤더 높이가 변하지 않게 한다. 0건이면 `확인 대기 (0)`로 접힌 한 줄만 보인다(기존의 0건일 때 `null` 반환을 없앤다).
- 접힌 상태에서는 지출 목록 위치가 로딩 전후로 변하지 않아야 한다.

## 7. 범위 밖

- 결제수단 합치기(두 이름 병합), 카테고리 관리, 정규식 표기, AI에 후보 목록을 주는 방식.

## 8. 제약 (변경 없음)

- DB 없음, 저장소는 Google Sheets만. OAuth 범위 `drive.file` + `drive.readonly` + `spreadsheets` 유지.
- OCR/알림 데이터는 자동 저장하지 않고 사람이 확인(알림 자동 매칭은 대기 행의 결제수단 값만 채우며, 지출로 확정하는 것은 여전히 사용자 확인).
